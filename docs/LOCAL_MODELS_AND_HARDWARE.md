# 로컬 모델과 현재 Mac의 적합성

2026-09-09 추가 조사와 구현 smoke. 사용자는 강의·회의 모두 사용하며 로컬 전사를 선택했다. 요약은 Qwen3 4B MLX 4bit를 기본 후보로 구현했다. 고정 모델 파일을 별도 검증 폴더에 받아 SHA-256을 확인하고, 합성 한국어 음성으로 실제 로컬 Whisper 전사와 Qwen 로딩·생성을 실행했다. 이 짧은 smoke는 실제 강의·회의 품질 판정이 아니다.

## 1. 현재 기기에서의 결론

읽기 전용 시스템 조회 결과는 **Apple M1 Pro, 통합 메모리 16GiB, MacBookPro18,1, macOS 26.6.2**다. 칩·메모리·OS만 확인했고 GPU 코어 수·가용 메모리·디스크 여유·실제 추론 속도는 확인하지 않았다.

이 사양이라면 **로컬 STT를 우선 시험할 가치가 충분하다**. 별도 GPU나 새 Mac 구입을 먼저 전제하지 않는다. 권장 실험은 WhisperKit 다국어 large-v3 Turbo 계열로 전사한 후 모델을 해제하고, Qwen3 4B 4bit로 목적별 요약을 시험하는 것이다. 사용자의 용량·RAM 선호를 반영한 선택이며, 실제 품질·자원 부담은 검증한다.

이는 실행 가능성을 판단한 설계 권고다. ‘한국어 전사 정확도가 충분하다’, ‘회의 요약이 클라우드와 동등하다’, ‘1시간 오디오가 몇 분 만에 끝난다’는 결론은 샘플 시험 전에는 내리지 않는다.

## 2. 로컬 설치가 의미하는 것

앱의 추론 라이브러리와 별도로 **학습된 가중치 파일을 한 번 다운로드**한다. 사용자가 모델을 직접 학습하거나 Python 환경을 관리할 필요는 없도록 설계할 수 있다. 다운로드 완료 후에는 설치된 모델로 오프라인 전사가 가능하다.

완전 로컬 구성에는 두 모델이 필요하다.

| 단계 | 하는 일 | 권장 시험 후보 |
| --- | --- | --- |
| STT | 소리→전체 텍스트 | WhisperKit의 다국어 large-v3 Turbo 압축 모델 |
| 요약 | 전체 텍스트→강의/회의 구조화 정리 | Qwen3 4B MLX 4bit, 8B는 참고 비교만 유지 |

WhisperKit은 실행 라이브러리이고 Whisper가 전사 모델 계열이다. Qwen은 텍스트 요약 후보이며 Whisper의 대체 전사 모델로 쓰는 것이 아니다. 이름 뒤 `.en`이 붙은 영어 전용 Whisper 모델은 한국어 후보에서 제외한다.

## 3. 다운로드 용량과 메모리

### 공식 파일 크기

| 구성요소 | 확인한 다운로드 크기 | 근거 |
| --- | ---: | --- |
| WhisperKit `openai_whisper-large-v3-v20240930_626MB` | 626,718,238 bytes | [Argmax 모델 폴더](https://huggingface.co/argmaxinc/whisperkit-coreml/tree/main/openai_whisper-large-v3-v20240930_626MB) |
| Whisper `openai/whisper-large-v3` tokenizer | 4,384,545 bytes | 앱 고정 manifest의 8개 tokenizer 파일 |
| Qwen3-4B-MLX-4bit runtime assets | 2,278,969,756 bytes | [Qwen 공식 파일](https://huggingface.co/Qwen/Qwen3-4B-MLX-4bit/tree/main) |
| Qwen3-8B-MLX-4bit | 약 4.37GB | [Qwen 공식 파일](https://huggingface.co/Qwen/Qwen3-8B-MLX-4bit/tree/main) |

고정 revision 기준 STT Core ML+tokenizer+4B runtime assets는 합계 2,910,072,539 bytes(약 2.91GB, 2.71GiB)다. 컴파일 캐시·업데이트용 임시 파일·녹음 원본은 추가 공간이다. **초기 여유 공간 10~15GB 확보**를 운영상 권장한다. 이는 공식 최소 사양이 아닌 설치·캐시·짧은 녹음 실험을 위한 여유 예산이며 장기간 원본 보관 공간은 별도로 필요하다.

### 실행 메모리는 다운로드 크기와 다르다

가중치뿐 아니라 실행 버퍼, 디코더 상태, 요약 모델의 KV cache, 입력 길이, GPU/Neural Engine 자원, 앱·OS가 메모리를 쓴다. 4bit 요약 모델이라도 긴 전사를 한 번에 넣으면 메모리가 크게 늘 수 있다.

다른 런타임의 참고값으로 whisper.cpp 공식 README는 small에 약 852MB, medium에 약 2.1GB, large에 약 3.9GB의 실행 메모리를 제시한다. **이는 whisper.cpp의 해당 구성 수치이며 WhisperKit 압축 모델이나 ListenUp 전체 메모리로 대입하면 안 된다.** [whisper.cpp 메모리 표](https://github.com/ggml-org/whisper.cpp#memory-usage)

현재 기기의 설계 예산은 로컬 STT 프로세스 peak RSS 4GB 이하, 4B 요약 6GB 이하를 시험 목표로 잡는다. **이 값은 모델 실측치나 공식 요구량이 아니라 초과 시 구성을 줄이기 위한 앱의 초기 자원 예산**이다. 시스템 memory pressure와 swap 증가도 함께 측정한다.

## 4. 사양별 선택 지침

아래는 macOS 앱을 위한 보수적 설계 권고이며 공식 지원 하한이나 성능 보증이 아니다. 칩 세대만큼 RAM, 메모리 대역폭, 다른 앱 부하, 발열 조건이 중요하다.

| Mac 환경 | 로컬 STT | 로컬 요약 | 권장 방식 |
| --- | --- | --- | --- |
| Apple Silicon 8GB | 압축 STT 또는 작은 모델부터 시험 | 짧게 나눈 4B도 메모리 압박 가능 | 종료 후 순차 처리, 필요하면 클라우드 요약 선택 |
| **M1 Pro 16GB: 현재 기기** | **압축 large-v3 Turbo 계열 우선 시험** | **4B 기본, 8B 설치 제외** | **STT 종료·메모리 해제 후 요약, 제한된 입력 길이** |
| Apple Silicon 24~32GB | 큰 모델·여러 옵션 비교 여유 | 8B 이상 비교 여유 | 정확도 개선이 있을 때만 더 큰 모델 채택 |
| Intel Mac | whisper.cpp CPU/지원 가속 경로 시험 | 느린 후처리 가능성, 별도 평가 | 네이티브 cloud 경로 우선 검토, 로컬은 호환성 분기 |

현재 기기에서 첫 시도부터 STT·8B 요약·화상회의·무거운 개발 도구를 모두 동시에 실행하는 설계는 피한다. 녹음 중에는 저장을 우선하고 추론을 종료 후 수행한다. 실행 메모리를 줄이기 위해 오디오·텍스트를 청크로 처리하고 모델 하나만 메모리에 올린다.

## 5. 어느 정도 성능을 기대할 수 있는가

통합 smoke에서 14.74초 합성 음성의 Whisper→Qwen 전체 프로세스는 Core ML 준비를 포함해 264~268초였고, Qwen만 고정 4문장 전사에서 실행한 1회는 19.11초와 약 3.415GB peak footprint였다. 모델·바이너리가 바뀐 두 전체 실행 모두 Core ML 준비가 반복되어 cold/warm 차이를 아직 확정할 수 없다. 이 값은 짧은 합성 입력의 통합 진단이며 60분 처리 시간을 외삽하거나 품질 합격을 주장하는 자료가 아니다.

### 전사 속도

WhisperKit 연구에는 M3 Max의 Neural Engine을 사용한 짧은 스트리밍 응답 지연 측정이 있지만, 이는 M1 Pro에서 한국어 1시간 녹음을 전사하는 소요 시간과 다르다. 논문의 영어 데이터 결과나 짧은 부분 응답 지연을 그대로 한국어 정확도·전체 처리 시간으로 제시하지 않는다. [WhisperKit 연구](https://arxiv.org/html/2507.10860v1)

이번 앱에서는 RTF(오디오 길이 대비 처리 시간)로 측정한다. 아래는 **계산 예시이며 예상 성능이 아니다**.

| 실측 RTF가 이 값이라면 | 60분 녹음의 STT 시간 |
| ---: | ---: |
| 0.10 | 6분 |
| 0.25 | 15분 |
| 0.50 | 30분 |
| 1.00 | 60분 |

로컬 출시의 잠정 목표는 warm STT RTF ≤0.25, 60분 입력의 전사+요약 25분 이내다. 느리더라도 사용자에게 유용할 수 있으므로, 시간 목표와 품질 기준을 별도로 보고하고 사용자 선호에 따라 재평가한다. 최초 모델 로딩·Core ML 준비 시간도 따로 기록한다.

### 전사 정확도

깨끗한 단일 화자 강의와 잡음·동시 발화가 있는 회의는 다른 조건이다. 압축 Turbo로 시작하되 전문용어·숫자 품질이 부족하면 동일 원본으로 큰 다국어 모델을 비교한다. 속도가 빠르다는 이유로 정확도가 떨어지는 설정을 기본으로 채택하지 않는다. 원본 보존으로 재전사할 수 있게 한다.

### 요약 품질

Qwen3 계열은 다국어 텍스트 모델이며, 공식 4B·8B 모델과 4bit 파일이 제공된다. 모델 크기는 품질의 유일한 기준이 아니므로 4B를 실제 한국어 전사·스키마에서 평가한다. 8B는 기본 설치하지 않는다. [Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B), [Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B)

4B는 낮은 자원 사용의 출발점, 8B는 복잡한 회의의 결정·담당자·이견 구분을 개선하는지 확인할 비교 후보다. ‘8B면 충분’이라는 보증은 하지 않는다. 근거 없는 담당자·기한 생성은 모델 크기와 무관하게 출시 실패로 처리한다. 모델 선택은 최신성보다 한국어 평가 결과와 앱 통합 재현성을 우선한다.

## 6. 현재 기기에 맞춘 권장 실험 순서

1. 한국어 강의 10분과 회의 10분을 준비하고 정답·핵심 용어·결정 항목을 주석 처리한다.
2. WhisperKit 압축 모델 한 개만 설치해 동일 파일을 cold 1회, warm 3회 처리한다.
3. CER·용어·숫자 오류·RTF·peak RSS·memory pressure·발열 상태를 저장한다.
4. STT 모델을 해제한 뒤 Qwen3 4B로 정답 전사와 실제 전사를 각각 요약한다. 입력 예산은 우선 4,000~6,000토큰, 출력은 최대 1,500토큰으로 제한하고 부분 추출→종합한다.
5. 4B의 지연·메모리 부담을 측정하고 입력 청크 길이를 조정한다. reasoning/non-thinking 설정과 최대 토큰을 고정한다. 8B로 자동 승격하지 않는다.
6. 사용자가 외부 전송을 허용한 경우에만 같은 샘플을 선택한 클라우드 후보와 비교한다.
7. 파일별 정확도·교정 시간·총 지연·자원·비용을 바탕으로 로컬/혼합/클라우드를 확정한다.

시스템이 바쁜 조건의 시험을 추가하고 로컬 모델 실행 중 새로운 녹음을 시작하면 추론을 pause/unload하여 캡처에 우선권을 준다. 20분 소규모 시험으로 방향을 정한 뒤 [전체 평가 계획](MODEL_SELECTION.md)의 보류 세트와 2시간 안정성 시험을 통과시킨다.

## 7. 앱 설치·운영 경험에 추가할 요구사항

- ‘로컬 전사’, ‘로컬 전사+로컬 요약’, ‘클라우드’의 처리 위치를 각각 표시한다.
- 모델 선택 시 다운로드 크기·필요 여유 공간·설치 상태를 표시하고 사용자가 설치 동작을 누른 뒤 다운로드한다.
- 중단 다운로드 재개, checksum 검증, 모델 버전 고정, 삭제·교체를 지원한다. 업데이트는 기존 동작 모델을 검증 전 삭제하지 않는다.
- 앱 설치 후 모델을 앱 안에서 별도로 받는 방식으로 확정했다. 기본 모델 폴더는 Application Support의 ListenUp/Models이며 설정에서 변경할 수 있다. 녹음 결과 폴더와 분리하고 세션마다 모델을 복제하지 않는다. 다운로드·검증·로딩 완료 후 오프라인 사용이 가능하다.
- 앱 재실행 시 모델이 없으면 녹음은 허용하고 후처리만 대기한다. 모델 다운로드에는 음성 전송이 필요하지 않다.
- 설치 완료 후 오프라인 모드 시험에서 음성·텍스트 네트워크 요청이 0건인지 확인한다. 자동 클라우드 fallback은 금지한다.
- 순차 로드·해제, memory pressure 대응, 취소 가능한 추론, 장시간 UI 응답 유지가 필요하다.

네이티브 요약 런타임 후보는 MLX Swift LM이다. 실제 선택한 안정 버전이 해당 Qwen 모델·tokenizer·macOS target을 지원하는지 컴파일 및 짧은 생성 시험으로 확인한다. 최신 main의 기능이나 macOS 27 전용 bridge를 현재 최소 OS에 그대로 적용하지 않는다. [MLX Swift LM 공식 저장소](https://github.com/ml-explore/mlx-swift-lm)

## 8. 결정 상태

사용자는 **로컬 전사로 진행**하기로 선택했다. 요약의 기본 검증 후보는 Qwen3 4B MLX 4bit이며, 품질 합격이 확인된 것은 아니다. 제품의 녹음·파일·재생 구조는 그대로 유지하며, 평가 결과에 따라 STTProvider와 SummaryProvider 구현만 선택한다.

클라우드 비용은 [모델 선택 문서](MODEL_SELECTION.md), 로컬 평가·설치·자원 관리 작업은 [구현 TODO](IMPLEMENTATION_TODO.md)의 L 시리즈를 따른다.
